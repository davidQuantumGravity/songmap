# Sound design in AI Lab

Instrument comparisons have two sound-design controls below the take cards. They work with native synthesis, SFZ sample voices, and existing modular patches. Riff, arrangement and saved-snippet comparisons keep their existing controls.

**Shape this sound** edits the selected A or B audition. Brightness and body are bipolar controls with a neutral center. Attack, tightness and grit start at zero, which preserves the source. Adjust the sliders and press **Preview shape**. This renders a disposable, isolated-part audition with the same notes and per-note envelopes as a saved take. Changing a knob stops an obsolete audition; preview again to hear the new settings. The selected loop range is respected. Previewing does not create candidates, choose a favorite, or record feedback.

**Blend A ↔ B** plays both isolated source parts on one Web Audio clock. Its slider changes gains smoothly during playback: A has gain `1 - blend` and B has gain `blend`. These complementary gains keep identical shared material at the same level. At either endpoint, choose the existing take; saving is enabled for intermediate mixtures. For a drum-piece comparison the browser auditions the whole kit, but only that piece changes in the saved recipe. Audition gain makes quiet passages audible without changing source balance or being written into the song. The shape and blend preview players pause the ordinary A/B player, and vice versa.

**Save shaped take** or **Save blended take** creates a challenger using the normal durable candidate/render workflow. The chosen favorite, text draft, feedback history and source files remain intact. Voting pauses during an unsaved audition so it cannot be mistaken for a saved A/B take. Previewing sets the listening context to the isolated part. The user can vote on saved takes, ask the AI to revise, or use **Review & apply** and undo. To combine both tools, save a blend and shape the resulting take. The 24-take session limit still applies.

## Recipe format

A recipe is saved inside the score, independently of the Lab database. Compact scores use the existing `set` syntax; YAML uses a `sounds:` mapping. For example:

```text
set sounds.warm_mix={"a": {"use": "bass/sub", "params": {}}, "b": {"use": "bass/rubber", "params": {}}}
inst bass=sound/warm_mix(blend=.35, tone_brightness=-.2, tone_body=.1)
```

Each source stores its actual voice reference and numeric overrides. Modular patch sources also embed their wiring under `patch`, so another score cannot reinterpret the saved sound through a different local patch with the same name. The engine passes the same pitch, velocity, gate, seed and round-robin slot to both voices, blends their note audio, then applies the outer tone controls. Native style and per-note overrides continue to reach source parameters they support. Prefixing a parameter with `a.` or `b.` addresses one source specifically. A source can itself be a sound recipe; nesting is limited to four levels and eight leaf voices. Cycle detection rejects recursive definitions.

Recipe names generated by the Lab use their definition hash. Apply copies the definitions into each selected score and rejects conflicting definitions with the same name. Musical sections and other voices remain unchanged. Both source libraries remain in the render's sample provenance and license output. Sample sequences keep their full note counter beyond eight notes. Mono and stereo sources retain their respective pan laws before blending; voice gain and pan survive compact-format edits. Cache identity includes the recipe dependencies and placement.

| Parameter | Range | Effect |
|---|---|---|
| `blend` | 0–1 | Complementary A/B source balance; ignored when there is only A |
| `tone_brightness` | −1–1 | High shelf at 3.5 kHz, up to ±12 dB |
| `tone_body` | −1–1 | Low shelf at 180 Hz, up to ±9 dB |
| `tone_attack` | 0–1 | Adds a smooth per-note fade-in, up to 80 ms |
| `tone_tightness` | 0–1 | Adds per-note exponential damping relative to the note's gate |
| `tone_grit` | 0–1 | Adds tanh saturation, with drive up to 10 |
| `tone_width` | −1–1 | Stereo side gain from 0× to 2×; original at 0, mono at −1 |
| `tone_vibrato` | 0–1 | Added pitch vibrato, delayed 180 ms and faded in over 300 ms, up to 35 cents; retains recorded vibrato |
| `morph_x`, `morph_y` | 0–1 | For four-source recipes only: bilinear crossfade across A/B/C/D |

Neutral tone controls leave the source samples unchanged. Neutral blends at 0 and 1 reproduce the respective source note audio. Blending is audio layering; it does not interpolate a physical instrument's construction or invent an unrecorded articulation. A blended drum note uses the dominant source's choke identity, rather than independent choke graphs for both layers.

The browser blend is immediate. Shape previews and saved score curves require rendering.
The [Expression editor](EXPRESSION_ARTICULATION_RESPONSE.md) now moves source balance,
tone, volume and added pitch/vibrato within held notes. Preview mastering can differ
from a full-song render, and isolated-part auditions exclude shared effect returns.

Named orchestral and jazz palettes also appear under **Rack → sound · continuous palettes**.
They resolve from `songmap/instruments/sounds.yaml`, with score-owned definitions taking
precedence. A four-source definition must include all `a`, `b`, `c`, `d` entries. At X/Y
corners its source gains are exactly 0/1; at intermediate positions they sum to one. Independent
source parameters use prefixes `a.` through `d.`. AI Lab's shape controls expose the matching
mix schema and preserve the layout when saving a shaped take. See [ENSEMBLE_PALETTE.md](ENSEMBLE_PALETTE.md)
for source labels, ranges, licensing and within-note control limits.

## Validation

`python -m pytest -q tests/test_sound_design.py tests/test_instrument_lab.py tests/test_music_lab.py` covers endpoints, neutral processing, nested recipes, note overrides, cache invalidation, sample provenance, unchanged backing, SM/YAML round trips, apply/undo, validation, and preview/save persistence boundaries.

`python tools/verify_sound_design.py` launches an isolated fixture server and database. It exercises shape audition/save, live synchronized blend gains, blend save, feedback-draft preservation and mobile width. It never writes to the creator's comparison database or scores. Screenshots and its receipt are written under `.songmap/instrument-lab/`.
